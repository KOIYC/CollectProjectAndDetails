## 摘要正文

最近做了个小项目 BoomBit ，一个专门提供 Claude API 接入的中转站。  地址： https://boombit.online/  之前看过不少 API 聚合平台，基本都是 OpenAI 、Claude 、Gemini 、DeepSeek 什么都接。功能确实丰富，但对于主要使用 Claude Code 的开发者来说，其实大部分模型都用不上。  所以这次做的时候，我想换个思路：不追求模型数量，只围绕 Claude 做一套相对简单的 API 服务。  ## 为什么只做 Claude ？  主要还是想把精力集中在一个地方。  Claude 的接口不只是普通的文本对话，实际使用 Claude Code 时，还会涉及工具调用、流式输出、Thinking 、Prompt Cache 等功能。  如果中间层对协议处理得不够完整，就可能出现普通聊天没问题，但一到复杂的编码任务就报错的情况。  因此 BoomBit 优先采用 Anthropic 原生协议，同时提供 OpenAI 兼容接口，尽量减少客户端接入时需要做的改动。  ## 具体怎么做的？  目前主要围绕几个方面：  - 接口尽量保持 Anthropic 原生格式，兼容 Claude Desktop 等客户端。 - 把线路分成「 Claude Code 专用」和「可外接」两种，避免不同使用场景混在一起。 - 每个 API Key 可以独立设置额度、有效期，方便不同项目分别管理。 - 记录每次调用的 Token 消耗和费用，包括缓存相关的用量。 - 支持 CC Switch 导入，减少手动修改配置的步骤。  Claude Code 接入也比较简单，主要就是更换接口地址和 Key 。  当然，中转层毕竟多了一层依赖，稳定性、响应速度、异常处理这些都需要持续优化。目前也不敢说已经做到多完善。  ## 关于定价  这部分可能是大家比较关心的。  目前没有做包月套餐，而是按照实际 Token 消耗计费。  价格直接参考 Anthropic 官方的模型单价，再乘以对应线路的倍率：  - **Claude Code 专用线路：0.2x** - **可外接线路：0.22x**  举个例子，如果按照官方价格计算的一次调用是 1 美元，那么专用线路对应的费用就是 0.2 美元。  两个线路价格不同，主要是为了区分专用客户端和通用 API 接入场景。  我个人更倾向于按量计费，因为大家的使用频率差异很大。偶尔写点代码和每天高强度跑 Agent ，消耗完全不是一个量级。  另外，缓存 Token 也单独计费，不是把所有 Token 统一按照输出价格计算。每次请求的消费明细都能在后台查看。  ## 目前的情况  站点已经开放…
