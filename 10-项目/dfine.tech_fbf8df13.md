## 摘要正文

最近开源了一个自己用 Rust 开发的项目：**UnifyTerm**。  现在终端项目越来越多，从 Ghostty、WezTerm 到各种 AI Terminal，大家都在探索终端的不同形态。  所以我也一直在思考一个问题：在已经有这么多优秀终端的情况下，还有什么值得做？  我的切入点不是再做一个更快的终端模拟器，也不是简单地给终端增加一个 AI Chat，而是希望解决几个实际问题：  1. Windows、macOS、Linux 之间的命令环境不一致。 2. 命令历史只是简单记录，缺少工作目录、执行状态等上下文。 3. 终端仍然主要是文本交互，查看图片、文档等内容需要频繁切换工具。 4. AI Agent 越来越多地操作终端，但它们并不总能准确理解当前环境有哪些可用能力。  于是有了 UnifyTerm。  ## 一、跨平台统一命令环境  UnifyTerm 不是一个新的 Shell，而是一个跨平台桌面终端应用，兼容现有的 PowerShell、cmd、bash、zsh、fish。  它提供了一套统一的 Unix 命令工具。  例如在 Windows 下，不需要安装 WSL 或 Git Bash，就可以直接使用：  - `cat`、`ls`、`pwd` - `grep`、`find`、`sed`、`sort` - `jq`、`diff`、`xargs`  目前 Windows 内置 99 个命令，Linux 内置 114 个命令。  除了命令本身，还处理了不同平台的路径格式和通配符展开问题。  希望达到的效果是：同样的命令和脚本，在不同操作系统上尽可能保持一致。  ## 二、让命令历史真正有用  传统终端的命令历史大多只关注输入过什么。  UnifyTerm 使用 SQLite 在本地记录：  - 命令内容 - 执行时的工作目录 - 退出状态 - 执行耗时  输入命令时，会根据历史记录和当前工作目录进行匹配。  例如在项目 A 中经常执行的命令，在进入项目 A 后会获得更高的搜索优先级。  另外，历史记录可以在不同机器之间迁移，Windows 上记录的命令也可以在 Linux 上使用。  密码、Token 和 Key 等敏感内容会在保存前过滤。  我希望命令历史不只是一个日志，而是逐渐成为开发者自己的本地命令知识库。  ## 三、让终端不再只有文本  终端其实可以承载更多内容。  UnifyTerm 提供了几个直接可用的能力：  ```bash # 查看图片 ut view photo.png  # 播放视频 ut view clip.mp4  # 阅读 Markdown ut md README.md ```  …
