## 摘要正文

女朋友干前端的，公司做医疗的，业绩比较差，裁员了。  她买了小红书副业课，赛道选来选去，想做情绪漫画  本来想着网站开源的漫画工具那么多，做个工具还不简单吗，实施过程中还是踩了不少坑  ![Manhwa AI editor](  )  用 TanStack 做了一个： https://mangaai.me/ 用 next.js 做了一个： https://www.manhwaai.net/  全程 codex 5.5 去改开源项目 https://github.com/Reuben-Sun/OpenKoma/ （这个也是 gpt 搜出来的） vercel + cloudfare 部署，supabase 数据库  ## 尝试 1：Tldraw 失败告终 因为 gpt 说这个框架很强大并且极力推荐。 Tldraw 的核心是无限画布。虽然很强，但是改起来对技术要求高，一个对话气泡就调试了 2 小时。不太适合固定尺寸页面、可编辑气泡、可预测的页面布局的功能，只适合 node 技术深厚的大佬。  ## 最后选择 Fabric.js 最开始选的就是 Fabric.js ，实现了个大概的版本，效果不够好。 但后来轻信了 ChatGPT ，觉得新的 Canvas 库会更牛，所以中途换几次路线。 经历了前面几次尝试后，我重新做了调研，发现很多同类开源项目用的就是这技术，再看 Fabric.js 文档，才觉得它的数据模型和我的产品需求非常接近。  - 原生 Canvas 给了我完全的控制权，但几乎没有编辑器基础设施。 - Tldraw 和 Excalidraw 提供了完整的编辑环境，但它们主要围绕无限画布设计。 - React-Konva 位于两者之间，但状态同步和自定义交互代码会随着功能增加不断膨胀。 - Fabric.js 同样位于中间位置，但它的对象模型更加接近设计编辑器。  现在产品做出来了，有没有漫画行业的大佬给点产品需求和建议
