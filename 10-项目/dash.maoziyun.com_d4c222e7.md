## 摘要正文

先说结论：帽子云现在已经不只是一个静态网站托管平台了。网站、Web 应用、PostgreSQL 和 Redis，都可以放到同一个项目里管理。  最开始做帽子云，其实没想那么复杂。  当时我只想解决一个问题：能不能把 GitHub、Gitee 等代码仓库里的静态网站直接部署上线？不用自己买服务器、配环境，也不用折腾 Nginx 和 HTTPS。  于是，帽子云就这样开始了。  2024 年 12 月，我把它发布到了 V2EX：[当时的帖子](https://v2ex.com/t/1096024)。  没想到，这个小项目一直做到了现在。截至 2026 年 11 月 13 日，平台已经累计部署了 **4800 个静态网站**。  但这个数字也让我越来越清楚地看到：静态网站只是起点，一个完整的项目，远不止一个网站。   ![]( )  ![]( )   比如你开发了一个 SaaS 项目：  - 前端需要部署网站； - 后端需要运行 API 服务； - 业务数据需要 PostgreSQL； - 缓存需要 Redis； - 还要处理域名、HTTPS、日志和监控。   ![]( )   以前，这些东西可能需要在好几个平台之间来回切换。前端在一个地方，后端在另一个地方，数据库又是单独购买的。  服务一多，管理和排查问题都变得麻烦。  所以，这次我给帽子云做了一次比较大的升级：  **现在，网站、Web 应用、PostgreSQL 和 Redis，都可以放在同一个项目里管理了！**  ## 一、静态网站只是起点  目前支持的主要服务有：  **1. 静态网站**  支持从代码仓库部署静态网站，适合个人博客、企业官网、产品官网、文档站等场景。  部署免费，还提供边缘加速，不需要自己购买服务器。  **2. Web 应用**  除了静态网站，现在也可以运行真正的后端服务。  支持常驻容器，提供 Buildpack、Dockerfile 和镜像等部署方式。  无论是 Go、Node.js、Java，还是其他能够运行在容器中的应用，都可以部署。  Web 应用约 ¥9.45/月起，起步规格为 0.5 核 / 512 MiB，持久卷存储另计。  **3. PostgreSQL**  项目需要存储业务数据？直接创建 PostgreSQL 即可。  不需要再单独购买一台数据库服务器，可以和 Web 应用放在同一个项目里管理。  **4. Redis**  需要缓存、Session 或队列相关能力？也可以直接创建 Redis。  从网站到应用，再到数据库和缓存，常用的基础服务基本都齐了。  ## 二、为什么要把网站、应用和数据库放在一起？  以下…
