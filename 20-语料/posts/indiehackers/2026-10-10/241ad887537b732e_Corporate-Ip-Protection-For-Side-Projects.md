 Why I built the Side-Project IP Isolation Kit (and what I learned from 0 sales)
When building software side projects while working full-time at a tech company, there's always a subtle, lurking anxiety:
 “Does my employer own this code because I accidentally committed with my work email or used a broad PIIA contract?”
 As a software consultant, I saw this happen constantly—engineers unknowingly mixing git configs or neglecting basic prior-invention carve-outs before writing a single line of code.
 To solve this, I built the Side-Project IP Isolation Kit :
 Git Identity Scrubber: A quick local terminal setup/script to audit and override your git email/username on personal repositories, preventing work email leaks in commit logs.
Environment & PIIA Checklist: An actionable checklist to air-gap personal machines, AI subscriptions (Copilot/Cursor), and review standard PIIA employment agreement carve-outs.
Building in Public (Honest Metrics):
 Traffic: ~100+ views.
Sales: 0.
Current Focus: Testing copy, refining value proposition, and getting blunt feedback from the IH community to understand what's missing for software engineers evaluating this risk.
If you're building a side project while full-time employed, I'd love your thoughts on how you handle IP air-gapping and contract carve-outs!
