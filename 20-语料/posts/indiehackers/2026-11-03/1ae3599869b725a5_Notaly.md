October 31, 2026
 AI summaries of your notes go stale. I built a Markdown notes app where AI-built views stay up to date instead.
Hi IH, I'm Seungmin, a developer in Korea. For about two years I've been building Notaly on the side. It's a desktop Markdown notes app where you describe a view of your notes and an AI agent builds it. The view keeps updating as you write. Here's how it got here, and I'd love your feedback.
 Where it started
 I've used Notion, Logseq, and Obsidian. Obsidian the longest, and I still use it. What kept bugging me was writing the same thing twice. I'd take meeting notes in one document, then write a summary or a plan somewhere else and type the same items again, or paste copies that slowly drifted apart.
 I wanted to write a line once, pull it into any other note, and edit it right there.
 Version one: every line is a record
 That's what I built first. Any line in Notaly can carry fields at the end, like #task=todo&priority=high . A query pulls every matching line from across your notes. The results aren't copies, so editing one changes the original line.
 Nobody wrote queries, including me
 It worked. I showed it to people and got no reaction at all. And I wasn't writing queries in my own notes either. I had built the whole app around a feature I didn't use myself.
 Version two: desks
 Instead of asking people to write queries, I started looking for something easier and more useful I could build on top of them.
 I write a lot of to-do notes and meeting notes, and formatting them by hand from a blank page every time got tedious. Notaly could already open HTML files inside the app, the same way it opens notes, so I built on that.
 I added a way to make small HTML apps that read and write your notes, and called them desks. When you add a meeting or a to-do through the Meeting notes or Tasks desk, it saves a properly formatted note. A desk writes plain Markdown lines into your notes, so other desks can use them too. A to-do you add in Tasks is the same line on the Kanban board, and moving the card updates the note. There are eleven official desks now, and I'll keep adding more.
 Then I put a terminal inside the app. You can run Claude Code or Codex there, describe the view you want, and the agent builds the desk. Notaly also ships an SDK, a CLI, and docs for the agent to work from. In the GIF above, I asked in one paragraph for a desk that ranks the feature requests from my customer calls.
 A desk doesn't go stale
 You can build views like this in other apps too. In Obsidian you can set one up with Dataview, Bases, or a plugin, or have an AI agent write it for you. What I cared about was what happens after the AI is done.
 When you ask an AI about your notes, you usually get a snapshot, like a summary or a page with the results pasted in. It only reflects the notes you had at that moment. Write a new note the next day and it's already out of date, so you ask again.
 In Notaly, the agent builds a desk, and a desk doesn't keep a copy of your notes. It reads them, and reads them again whenever a note is added or changed.
 Say you write up every customer call and tag each feature request. In the GIF below, the Feature requests desk already has a couple of weeks of calls in it. I add one line to today's call, and Slack alerts moves up to second place. I didn't refresh the desk or ask the AI again.
 What it doesn't do yet
 Desktop only (macOS and Windows). No sync, no mobile app.
The Windows build isn't code-signed yet, so you'll see a SmartScreen warning.
Building a desk with AI needs Claude Code or Codex, which you install and sign in to with your own account. Notes, queries, and every desk work without AI.
The desk gallery in the app only lists official desks. You can export a desk you made as a file, but there's no public listing yet.
It's free and needs no account. I don't know yet how it will make money, and that's part of why I'm posting here.
Why a database, not Markdown files
 Notes in Notaly are Markdown text, but they're stored in a SQLite database on your computer instead of as .md files. I know a lot of people want plain files, so here's why I did it this way.
 Desks treat every line as a record. The Feature requests desk has to find every #request= line across all your notes, and do it again each time a note changes. With plain files, that means reading every file again, or keeping a separate index in sync with files that can change underneath it. Desks also write back to single lines. When you move a Kanban card, the app has to change exactly that line without overwriting something you just typed in the same note. In the database, every line is indexed with its fields. Before a desk writes to a line, the app checks whether the line changed since the desk last read it. If it did, the desk reads it again first.
 I didn't want that to mean lock-in. The database is a single SQLite file, so you can open it with any SQLite tool. You can export all your notes to Markdown at any time, with tags and fields kept at the end of each line. And backing up is just copying that file while Notaly is closed.
 If you try it
 On first launch, Notaly installs Tasks and Kanban and opens the board next to today's note. Type a to-do in the note and it shows up as a card. If you're coming from Obsidian, Notion, or Logseq, File > Import… brings in your vault, export, or graph.
 What I'd love feedback on
 Does having an AI agent build small apps on top of your notes sound useful to you?
What desk would be useful for your own notes? Describe the view you'd want.
You can try it here: https://notaly.dev
 Thanks for reading. I'm happy to answer anything about the build.
seungmin
