07
 Questions
Quick answers .
 Sorted by what you are trying to do.
The basics
Does gitby replace GitHub?
 + No. Your repositories stay on GitHub and you keep using git. gitby connects through your GitHub account and adds file claims, notes, presence, chat, and access requests on top.
 Does gitby ever see my code?
 + gitby never stores your code. Pushes made through gitby pass through its push service on the way to GitHub, and the dashboard's diff view fetches changes from GitHub for your browser; neither keeps a copy. What gitby stores is coordination data: paths, claims, requests, notes, team membership, and activity. No file contents, diffs, note text, or chat text ever enter its statistics.
 How does gitby make a file read-only?
 + It changes the file permissions your operating system already enforces, so the rule works in any editor. A file someone else holds is read-only for you. By default every file you have not claimed is read-only too; a repository can instead be set to claim on edit, where files stay writable and a file is claimed as you edit it.
Day to day
What if a teammate needs a file I claimed?
 + They press t to ask for it. You can hand it off from the terminal or talk it through in chat first. Every request, grant, and denial is recorded with who did it and when.
 Do I still need a second terminal for git?
 + Commit, push, branch switch, per-file sync with a merge step, revert, the commit graph, reflog, diffs, and worktrees are all in the gitby window, and a push is blocked before it leaves if it carries files you do not hold. A terminal tab is there for everything else.
 What happens to a claim when I go offline?
 + It stays yours. A claim ends only when you release it, hand it off, or a team owner steps in. If you are away past the team's threshold the file list marks it stale so others know to ask.
What it measures
What does my team lead see about me?
 + Team-level numbers: handoffs, hold times, contention, and stale claims. Durations are medians, never averages, and there are no per-person leaderboards. Your own per-person view is visible to you alone.
 How does gitby count a prevented conflict?
 + Strictly. A second person had to actually want a file you held, through a request, a second editor showing up, or a blocked push, and the file had to reach a commit with one holder first. A toast never counts. These counts are being validated against live teams before the dashboard shows them.
Plans
Do AI agents follow the same rules?
 + An agent connected over MCP claims, releases, and asks for takeovers exactly like a person, under your account. You approve each claim on the Agents page, unless you run your agents in full access. Agent support is in validation and is not sold on any plan yet.
 How does pricing work?
 + Per team, flat, never per seat. Free covers 3 teammates and 2 repositories, and every plan includes claims, notes, and live sync. Paid plans raise the limits and add team chat: 5 teammates on Starter, 8 on Team, 20 on Team+, 50 on Enterprise.
