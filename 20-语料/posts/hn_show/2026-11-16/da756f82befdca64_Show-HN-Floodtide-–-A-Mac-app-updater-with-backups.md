 Settings, Updates A check every day, or every week
 Floodtide checks on its own and keeps a count in the menu bar, so the answer to “is this Mac up to date” is on screen without opening anything. Daily is the default.
Off until you say so Installs while you are elsewhere
 Install app updates automatically runs the same safety checks a manual Update All runs, nothing shortened. An app that is open updates as soon as you quit it; Floodtide never closes one for you. Once a week, if you like One notification, not one an hour
 Choose a notice after every check, or a single weekly one on a day you pick that lists everything waiting and carries the same Update All button. Checks still run on the interval either way, and the badge still counts.
Your hours Quiet hours
 Between the two hours you set, Floodtide checks as usual and the badge still updates, but it posts no notification and starts no update by itself. Set it to your working day, or to the night.
Per app One app out, the rest in
 Every app has its own Update automatically switch in the inspector. Switched off, the scheduled run leaves that app alone, its update stays on the list, and Update All still takes it when you press it yourself. A separate switch, on by default, decides whether major versions, 4.2 to 5.0, ride along in Update All at all; some developers charge for those, Floodtide cannot know which, and it never guesses.
Settings, Backups Somewhere of your choosing, for as long as you want

Automatic installing is off until you switch it on, and it never asks for your administrator password on an empty screen: an app that would need one is left for you, and the run says so.

 How Floodtide finds updates.
 Read from the sources.
 MacUpdater maintained exact version information for more than 100,000 apps and direct updates for thousands until that daily workload became unsustainable. Floodtide asks the sources that already know.
 The app's own feed
 Most indie Mac apps publish a Sparkle feed. Floodtide reads the URL from the app bundle itself and checks the developer's appcast directly. Authoritative, signed, current the second a release ships.
Homebrew casks, and formulae too
 A community-maintained index of Mac software. Floodtide reads the cask catalog directly, so Homebrew does not need to be installed, and safely matches 3,316 installable app bundles against it, pulling each vendor's official download and checking it against Homebrew's checksum, or, where a vendor publishes none, against the developer signature already on the installed copy. If you do run Homebrew, a pane of its own lists every cask, formula and tap it has installed and upgrades them through brew itself.
 It can also hand Homebrew the apps you installed by hand. An app Homebrew packages but did not install offers to be adopted: Homebrew records the copy already on your disk as its own and updates it from then on. Nothing is moved, replaced or downloaded again. There is an Adopt section listing every app this applies to, with Adopt All, so a Mac with years of hand-installed apps can be brought under Homebrew in one pass.
GitHub Releases and Electron feeds
 Plenty of apps publish neither an appcast nor a cask, but do ship releases on GitHub or an Electron update feed. Floodtide reads both, picks one unambiguous Mac build rather than guessing between several, verifies the SHA-512 an Electron feed publishes, and keeps the developer identity check in force either way.
Floodtide's own catalog, and yours
 A signed catalog researched by hand holds 2,003 apps, and 1,521 of the 4,837 on the coverage list are there because of it. It only ever names which source to read, so the reading still goes back through the sources above and nothing about verification is duplicated. You can also point any app at a Sparkle URL or a GitHub repository yourself, and your choice is checked before anything Floodtide discovers.
The Mac App Store, in place
 Store apps update inside Floodtide: the row ends on the new version like any other, no App Store window opens and no password is asked for. The optional Floodtide Installer carries its own signed and notarised copy of the tool that talks to the store, and the store work runs as you, not as an administrator. Floodtide reads what the store is offering on this Mac rather than Apple's public listing, which is why an iPhone or iPad app on Apple silicon no longer reads as outdated for weeks. An app over about 675 MB, an iPhone or iPad app, an account you are signed out of, and a version the store on your Mac is not offering still go to the store, and the row says which it is.
Named owners, and an honest uncovered list
 Apps Setapp or Microsoft AutoUpdate keep for themselves are labelled as theirs, with the pending version shown beside them instead of touched. If no source can prove a safe update, Floodtide says uncovered rather than guessing. One click can send an anonymous coverage request, and the exact payload is visible before sharing is enabled.
The updates it will not hand you.
 On purpose.
 An updater that offers everything it finds is easy to write and hard to trust. These are the cases Floodtide holds back, each one found on a real Mac and named in the row rather than hidden.
 Numbers that do not add up A jump like 5.92 to 2584447 usually means a wrong version number, a wrong app, or a developer who changed how they number releases, and Floodtide cannot tell which. The row says so, and that update is left out of Update All, selection runs and scheduled runs. Its own Update button still installs it. The rule was run over 868 real update pairs from real Macs first, and flagged none of them.
 An update your Mac cannot run A release needing a newer macOS than yours is named with the version it needs and no Update button, and clears itself after you upgrade. On an Intel Mac, a release published for Apple silicon only goes to a Needs Apple silicon page instead of being downloaded and then refused.
 The next app, wearing this app's name When a Homebrew cask moves to the next generation of an app, Bartender 6 to Bartender 7, MuseScore, Permute, that is a separate app, not an update to the one you have. The row follows the app's own feed and says what the cask now installs.
 A demo, offered to a licensed copy A release named a demo, trial or evaluation build by its version or its file name is never offered to a copy that is not one. Checked against all 7,735 Homebrew casks, so the editions people genuinely run are untouched.
 A download that is the build you have Some developers publish 7.50.1 as a file that reports itself as 7.50. That is not a failed update and is no longer shown as one: the row says the download offered is the build already installed, and offers it again when the file behind it changes.

 Why should I trust one person with my Applications folder? You should not have to take it on faith. Floodtide is signed with a Developer ID and notarised by Apple, and it holds every update to the same bar: each downloaded bundle’s code signature is verified, and the new build must be signed by the same Apple developer team as the copy it replaces, so a compromised download feed cannot swap a signed app for an impostor.  What happens when my trial ends? Floodtide keeps scanning and showing you what is outdated, free, forever. The Update buttons lock until a license is entered. Nothing nags on a timer.
 What if it is not for me after I have paid? Email raf@bhopstudio.com within 14 days of buying and the payment goes back through Stripe. The trial exists so that this rarely needs to happen.
 Can I install it with Homebrew? Yes. brew install --cask realm9758/floodtide/floodtide installs the same signed disk image from Floodtide’s own tap, and the app updates itself afterwards.
 Which update sources does it check? Six, live, per app: the app’s own Sparkle appcast, the Homebrew cask catalog, GitHub Releases, Electron update feeds, Floodtide’s own signed catalog, and the Mac App Store. You can also point an app at a Sparkle URL or GitHub repository yourself, which is a choice about which of those to read rather than a seventh source. The app’s own feed wins outright, and an app Homebrew installed stays Homebrew’s to update. Apps Setapp or Microsoft AutoUpdate manage are named as theirs rather than touched. If Homebrew is installed, a separate pane also covers its formulae and taps, upgraded through brew itself.
 Does it update Mac App Store apps? Yes, in place, since 1.3.0. Press Update on a store row and the app updates where it stands: no App Store window opens, no password is asked for, and Update All includes those apps alongside everything else. The optional Floodtide Installer carries its own copy of the tool that talks to the store, signed and notarised, and the store work runs as you rather than as an administrator, which is why nothing is asked of you. The Floodtide Installer is added once, from Settings, and the row says so when it is missing. Four cases still go to the App Store, and the row says which: an app whose download is larger than about 675 MB, such as Xcode or the Microsoft Office apps, because an update running for hours inside Floodtide would tell you less than the store does; an iPhone or iPad app running on an Apple silicon Mac, which only the store can update; an app you are signed out for or bought under a different Apple Account; and a version the App Store on your Mac is not offering, which the row shows without counting it as an update.
 What if an update breaks something? When backups are enabled, Floodtide keeps the previous version as a disk clone or archive for your chosen retention period. Undo Last Update restores a retained backup in one click. Floodtide also verifies each new bundle’s code signature before calling the job done, and a build signed worse than the one you had is refused and rolled back automatically.
 Why does it sometimes ask for my password? Some apps live in folders macOS protects. Replacing those needs the same administrator prompt any installer shows. By default Floodtide batches the whole run into one prompt; with Update one app at a time switched on and without Floodtide’s installer, each app asks in turn. It tells you before a prompt appears and never sees the password itself; macOS handles it.
 Is my data involved at all? The app makes network requests to check updates and validate your licence. Which apps and versions your Mac runs is shared once a day with no identifier, so the apps nobody can check get checked. On by default: the app tells you so on first launch, and Settings, Privacy shows the exact payload and turns it off at any time. The anonymous usage line stays off unless you switch it on, and nothing else about you leaves the Mac.
