Either build your pieces manually or have the AI generate them. Reviewing the generated pieces takes time, but not reviewing may have consequences...

Each ticket is a shape. Build it on the workbench or have the AI generate it.

Generated pieces can change shape after they land. The more you generate in a row, the more it happens.

Review a falling generated piece to see what it will become. Whatever it becomes drops into place.

Complete the required number of lines before the clock hits zero to successfully complete a sprint.

> I've been thinking a lot about how agentic coding is similar to gaming. Risk, reward, gambling, gratification, etc. I've been exploring that by vibe coding some satirical games that aim to reflect what agentic coding can be like in a deadline environment. This is one of those games.It's Tetris but:- You have to build a tetromino either manually or have AI "generate" it.- Generated tetrominoes might mutate after falling.- You can spend time to "review" generated tetrominoes as they fall to see how they will mutate.The theme is the risk/reward/pressure of agentic code vs manual vs reviewed agentic code in a deadline environment.
