# enmetu

 /enˈ me.tu/, Esperanto for "commit!"

Commits and syncs a git working tree automatically. Run it inside a repository: it commits after you stop editing, rebases onto the upstream, pushes, and pulls new commits.

## Why enmetu

Most auto-commit tools commit and push. enmetu also handles what goes wrong:

- Conflicts. A pull that conflicts is undone and held. Your commits stay local, and enmetu retries when either side changes. It never commits conflict markers and never force-pushes.
- No stash. A file it won't commit (conflict markers, invalid JSON) stays on disk and doesn't block the rest of the sync. Its pre-commit hook applies the same check to your own commits.
- Plain git. You and your agents keep using git. enmetu commits through its own index, waits up to 5 minutes on a partial staging, pauses during your merge or rebase, and never pulls over a file you saved since its last commit: it commits the save first, then pulls.
- Halts. A rewritten upstream, or a state it cannot verify, halts it. The halt survives restarts until you run `enmetu resume`.
- Status.`enmetu status` says whether your work is committed and pushed, and during a conflict prints the commands to end it.
- Commit messages. Can be generated by a script that gets the diff, e.g. with an LLM. Falls back to a default message.
- Dependencies. None besides git. Runs under Node or Bun, as a command or as a library.
- Tests. Real git against 28 conflict shapes (renames against deletions, binary files, case-only renames, line endings, a merge in progress), several clones converging on one history, and a stress test where a scripted person runs git next to enmetu as fast as it can, with every write checked against the final history.

## Prerequisites

- Node 24+ or Bun 1.4.4+
- git 2.38+
- A checked-out branch with an upstream, at least one commit, and a committer identity

## Install

### Node

Inside a repository:

```sh
npx @fluado/enmetu run

```

As a project dependency: `npm install -D @fluado/enmetu`, then `npx enmetu run`.

### Bun

Inside a repository:

```sh
bunx --bun @fluado/enmetu run

```

As a project dependency: `bun add -d @fluado/enmetu`, then `bunx --bun enmetu run`.

Keep `--bun`: without it, `bunx` runs enmetu with Node when Node is installed.

### Pinning

Add the version for repeatable runs: `@fluado/enmetu@0.4.0`.

## Commands

```text
enmetu run [--repo <path>]                          run in the foreground
enmetu status [--repo <path>]                       show whether your work is committed and pushed
enmetu resume [--repo <path>] [--accept-upstream]   clear a halt
enmetu hook pre-commit                              run the pre-commit check
enmetu --help | --version

```

| Exit code | Meaning |
| --- | --- |
| 0 | success |
| 1 | error, or the hook refused the commit |
| 2 | bad arguments or invalid config |
| 3 | halted, or resume refused |
| 4 | another enmetu runs on this worktree |
| 5 | repository not usable: bare, detached HEAD, no upstream, no commit, git too old, operation in progress |
| 130 | second Ctrl-C |

## Library

```js
import { startEnmetu, readEnmetuState } from '@fluado/enmetu'

const enmetu = startEnmetu({ repo: '.' })
const { liveness, record } = await readEnmetuState('.')
const exitCode = await enmetu.stop()

```

`commitMessage` lets the host program write each commit message:

```js
startEnmetu({
  repo: '.',
  commitMessage: async ({ root, parent, tree, runCommand, signal }) =>
    (await runCommand()) ?? 'Update notes',
})

```

- `git diff-tree -r ` in `root` lists the change.
- Return the message, its first line the subject, or `null` for `commitSubject`.
- `runCommand()` runs the person's `commitMessageCommand` on this change, at most once, and gives its message or `null`. With `commitMessage` set, the command runs only through this call.
- 10 seconds, then `signal` aborts and enmetu commits with `commitSubject`. So does a throw, or text without a subject; the log says `MESSAGE_WRITER_FAILED`.

## Configuration

`enmetu.config.json` at the repository root, optional:

| Key | Default | Meaning |
| --- | --- | --- |
| `quietMs` | `5000` | wait after the last change before committing |
| `maxDelayMs` | `60000` | maximum delay while changes keep coming |
| `pollMs` | `5000` | remote check interval |
| `commitSubject` | `"enmetu: local changes"` | commit message, and the fallback of `commitMessageCommand` |
| `installHook` | `true` | install the pre-commit hook |
| `skipJsonCheck` | `[]` | files exempt from the JSON check, such as `tsconfig.json` |
| `gitTimeoutMs` | `120000` | timeout per git command |
| `stateHistory` | `20` | state changes kept in the state file (0 to 100) |
| `partialStagingWaitMs` | `300000` | with a partial staging: commit everything after this long; `0` at once |
| `commitHooks` | `true` | run your commit hooks on enmetu's commits |
| `hookTimeoutMs` | `600000` | timeout per hook |

Unknown settings are logged and ignored.

### Your own settings

`git config enmetu. ` overrides the file for you alone, with the same names and checks: `--global` for all your repositories, `--local` for one clone. Local beats global. `enmetu run` logs each override at start, such as `CONFIG_FROM_GIT quietMs 2000 (git config, local)`.

```sh
git config --global enmetu.quietMs 2000
git config --local --add enmetu.skipJsonCheck tsconfig.json

```

`skipJsonCheck` takes one path per entry; the list of the most specific scope replaces the file's.

### Commit message command

A command that writes the commit message. Set it in git config only; enmetu ignores it in `enmetu.config.json`.

```sh
git config --global enmetu.commitMessageCommand 'your-command'

```

For each commit, enmetu runs it through the shell in the repository root:

- stdin: the patch, its first 64 KiB
- environment: `ENMETU_PARENT` and `ENMETU_TREE`, for your own `git diff "$ENMETU_PARENT" "$ENMETU_TREE"`
- stdout: the first line is the subject (at most 100 characters), the lines after it the body

After 5 seconds, or when the command fails or prints no usable subject, enmetu commits with `commitSubject` and logs `MESSAGE_COMMAND_FAILED`. The start line shows that a command is set, never the command.

Example: `examples/commit-message`, a Node or Bun script that names the changed document and adds a detail from a local model through llm, such as Apple's on-device model. Not part of the package.

| First word | Meaning |
| --- | --- |
| `safe` | committed and pushed |
| `pending` | uncommitted changes |
| `syncing` | unpushed commits |
| `waiting` | partial staging, or a hook rejected the commit |
| `attention` | conflict, push failure, orphaned commit, or failed cycle |
| `paused` | your git operation in progress, detached HEAD, or no upstream |

| `busy` | another git command holds the repository |

| `not running` | stopped, crashed, or never started |

## Logs

stderr, one line per event:

```text
2026-11-01T12:00:05.120Z INFO  c2  COMMITTED local changes
2026-11-01T12:00:05.122Z WARN  c2  EXCLUDED state.json: CONFLICT_MARKERS (opening and closing marker lines)
2026-11-01T12:01:10.341Z WARN  c15 UNPUSHED 2 local commits not on origin refs/heads/main

```

| Code | Meaning |
| --- | --- |
| `EXCLUDED` | file not committed: conflict markers or invalid JSON |
| `CONFLICT`, `UNPUSHED` | local commits not pushed |
| `WAITING`, `PAUSED`, `OFFLINE` | sync on hold |
| `HELD`, `RESTORED` | a file enmetu could not commit was set aside for a pull and put back; see Known limitations |
| `HALTED` | see `enmetu status` |
| `MESSAGE_COMMAND_FAILED`, `MESSAGE_WRITER_FAILED` | message from the fallback named in the line |
| `COMMIT_ORPHANED`, `STAGED_RESET`, `STAGED_REVERT`, `QUARANTINE_KEPT` | see Known limitations |

## State file

`.git/enmetu/state.json`, one line of JSON:

| Field | Meaning |
| --- | --- |
| `state` | `starting`, `synced`, `waiting`, `conflict`, `paused`, `busy`, `offline`, `push-failed`, `halted`, `stopped` |
| `reason` | code for `paused`, `waiting` and `halted` |
| `message` | summary |
| `since` | time of the last state change |
| `pushed` | last commit verified on the upstream |
| `unpushed` | local commits not on the upstream |
| `lastCycle` | id, outcome and time of the last cycle |
| `conflict` | conflicting commits |
| `history` | recent state changes |
| `orphaned` | commits left on no branch |
| `instance`, `version` | writer process, format version |

Stale after a crash; use `enmetu status` to check whether enmetu runs.

## Pre-commit

Installs `.git/hooks/pre-commit`, which refuses commits with conflict markers or invalid JSON. Bypass with `git commit --no-verify`.

Skipped when `core.hooksPath` is set or a `pre-commit` hook exists. Add this to your hook instead:

```sh
if command -v enmetu >/dev/null 2>&1; then enmetu hook pre-commit || exit 1; else echo "enmetu: pre-commit check skipped (enmetu not on PATH)" >&2; fi

```

## Known limitations

- One repository per process. No system service, no notifications.
- A partial staging pauses sync for up to `partialStagingWaitMs` (5 minutes by default), then enmetu commits everything. A case-only rename staged with `git mv` pauses it until you commit it.
- `commit-msg` and `prepare-commit-msg` hooks don't run on enmetu's commits; `commitMessageCommand` writes the message instead.
- Under Bun without file-watching permission, enmetu commits on its poll interval.
- Under Node on Linux, enmetu does not watch files: from Node 24.22, Node's recursive watch there can end the process (nodejs/node#66791). enmetu commits on its poll interval (`pollMs`, 5 seconds by default) and says so once at start (`WATCHER_FAILED`). Bun watches.
- A file written faster than a cycle runs keeps the pull waiting (`WAITING` with `TREE_CHANGING`) until it stops.
- A file enmetu cannot commit (invalid JSON, conflict markers, a rejected `pre-commit`) is set aside during a pull and shows the committed version from `HELD` until `RESTORED`, about 0.1 to 0.5 seconds. A save made meanwhile is merged back, or kept as a blob named in `QUARANTINE_KEPT` when it does not merge.
- A save landing in the milliseconds before git rewrites a file, inside a pull or its abort, is lost without a record.

Overlapping git commands:

| Symptom | Cause | Fix |
| --- | --- | --- |
| a file briefly showed old content | `HELD`: enmetu set it aside for a pull | wait for `RESTORED`; a `QUARANTINE_KEPT` line names a blob: `git cat-file -p ` |
| `cannot lock ref 'HEAD'` | raced enmetu's commit | after `INDEX_REPAIRED` in the log: `git reset --merge`, retry. If `not uptodate`: `git merge --quit`, `git reset` |
| `STAGED_RESET` | staged during enmetu's rebase | command in the log line |
| `QUARANTINE_KEPT` | your edit collided with a version enmetu held aside | command in the log line |
| `COMMIT_ORPHANED` | committed during enmetu's pull | `git cherry-pick -x` command in `enmetu status` |
| `STAGED_REVERT` | a refused `git merge` restored old content | `git restore` command in the log line |
| `could not write index` on a refused merge, or with older git (2.39) your edits gone after `would be overwritten by merge` | git stashed your edits | `git fsck --no-reflogs --unreachable`, then `git stash apply ` |
| `git rebase` fails, no rebase in progress | started together with enmetu's | `git rebase --quit` if needed, `git reset --merge`, `git checkout `, retry |

## Contributing

We built enmetu for ourselves. We use it every day at fluado and we're sharing it because it might be useful to others. It is the sync engine of faru, our git-native kanban board.

This is not a community project. We don't have the bandwidth to review PRs, triage issues, or maintain a roadmap for external contributors. If you open an issue with a good idea, we might pick it up when it aligns with what we need. No promises.
