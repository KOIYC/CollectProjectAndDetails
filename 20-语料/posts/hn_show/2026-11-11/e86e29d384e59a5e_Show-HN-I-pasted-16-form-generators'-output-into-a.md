What is in the HTML
The form element. action is Formgong's /submit address and method="POST" . That is all a browser needs to send it.
Two hidden inputs. access_key says which form this is. _lang sets the language of the thank-you page.
Labels. Every input has a label tied to it with for and id , so a click on the text focuses the field and screen readers read the name.
Error lines. Each field points at its own empty line with aria-describedby . When a field is wrong, the script writes the browser's own message there, so a screen reader reads it with the field.
Required fields. The required attribute. The browser stops an empty submit before anything is sent.
The select. Its first option is empty, so a required list makes people choose instead of sending the first item by accident.
The honeypot. A botcheck input moved off-screen and hidden from assistive tech.
A style block. A short block of CSS, every rule scoped to the form's own id. It cannot restyle the rest of your page.
An optional script. About thirty lines at the end. It keeps the visitor on the page and says “sent” only when Formgong answers success: true .
What makes a generated form actually send
 On 2 November 2026 we took the 16 sites on Google's first page for “html form generator” and “contact form generator” in the US, asked each for the same contact form (name, email, message), and pasted the result into an empty page unchanged.
0 of 16 gave a form that delivers a message as copied. 9 showed no code until we made an account. The other 7 posted to # , to a made-up action_page.php , to a placeholder sentence, or had no  at all.
0 of those 7 added spam protection : no honeypot, no CAPTCHA.
0 of 7 set autocomplete on name or email, so browsers cannot fill them in.
2 of 7 failed an axe-core accessibility check : one had three fields with no label, one had button text below the contrast minimum. 3 of 7 marked no field required.
Our copy does not deliver as pasted either: it carries the placeholder key fk_your_access_key until you paste your own free key. Then it sends. We ran axe-core 4.10.2 (WCAG 2.1 A and AA) on each snippet as pasted, with the same page around it.
Five things make the difference, and every copy here has them:
A real target. action is Formgong's /submit address with method="POST" .
Your key. The hidden access_key says which form this is. The placeholder fk_your_access_key is refused on purpose, so a forgotten key fails loudly instead of losing messages.
Field names. Each input has a name , made from its label. Without a name, the browser does not send the value.
An honest success message. The scripts say “sent” only when Formgong answers success: true . A wrong key, a full quota or a network error shows a message instead of a fake thank-you.
A honeypot. botcheck is off-screen and hidden from screen readers. Simple bots fill it, and Formgong files those posts as spam instead of sending them to you.
It works without JavaScript
 Delete the script and the form still sends. The browser posts the fields. Formgong stores them and answers with a redirect to a thank-you page. It only does that after the submission is saved. A wrong key or a failed check leads to an error page that says what went wrong.
With the script, the visitor stays on your page. It sends the same fields with fetch , reads the JSON answer, and shows “sent” only when it says success: true . Anything else shows Formgong's own message, such as a wrong key. The HTML guide has the hidden fields Formgong understands, such as _redirect for your own thank-you page.
