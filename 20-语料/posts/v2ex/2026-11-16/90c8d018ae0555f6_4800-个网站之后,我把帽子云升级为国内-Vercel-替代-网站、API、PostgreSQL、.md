## 正文

先说结论：帽子云现在已经不只是一个静态网站托管平台了。网站、Web 应用、PostgreSQL 和 Redis，都可以放到同一个项目里管理。

最开始做帽子云，其实没想那么复杂。

当时我只想解决一个问题：能不能把 GitHub、Gitee 等代码仓库里的静态网站直接部署上线？不用自己买服务器、配环境，也不用折腾 Nginx 和 HTTPS。

于是，帽子云就这样开始了。

2024 年 12 月，我把它发布到了 V2EX：[当时的帖子](https://v2ex.com/t/1096024)。

没想到，这个小项目一直做到了现在。截至 2026 年 11 月 13 日，平台已经累计部署了 **4800 个静态网站**。

但这个数字也让我越来越清楚地看到：静态网站只是起点，一个完整的项目，远不止一个网站。


![]( )

![]( )


比如你开发了一个 SaaS 项目：

- 前端需要部署网站；
- 后端需要运行 API 服务；
- 业务数据需要 PostgreSQL；
- 缓存需要 Redis；
- 还要处理域名、HTTPS、日志和监控。


![]( )


以前，这些东西可能需要在好几个平台之间来回切换。前端在一个地方，后端在另一个地方，数据库又是单独购买的。

服务一多，管理和排查问题都变得麻烦。

所以，这次我给帽子云做了一次比较大的升级：

**现在，网站、Web 应用、PostgreSQL 和 Redis，都可以放在同一个项目里管理了！**

## 一、静态网站只是起点

目前支持的主要服务有：

**1. 静态网站**

支持从代码仓库部署静态网站，适合个人博客、企业官网、产品官网、文档站等场景。

部署免费，还提供边缘加速，不需要自己购买服务器。

**2. Web 应用**

除了静态网站，现在也可以运行真正的后端服务。

支持常驻容器，提供 Buildpack、Dockerfile 和镜像等部署方式。

无论是 Go、Node.js、Java，还是其他能够运行在容器中的应用，都可以部署。

Web 应用约 ¥9.45/月起，起步规格为 0.5 核 / 512 MiB，持久卷存储另计。

**3. PostgreSQL**

项目需要存储业务数据？直接创建 PostgreSQL 即可。

不需要再单独购买一台数据库服务器，可以和 Web 应用放在同一个项目里管理。

**4. Redis**

需要缓存、Session 或队列相关能力？也可以直接创建 Redis。

从网站到应用，再到数据库和缓存，常用的基础服务基本都齐了。

## 二、为什么要把网站、应用和数据库放在一起？

以下对比基于 2026 年 11 月 15 日访问的公开资料，价格按 1 USD = ¥6.73 换算，仅作方向性参考。不同平台的配置、资源限制、流量、区域和计费方式并不完全一样，不能理解为同等规格对比。

相信不少开发者都用过 [Vercel](https://vercel.com/) 和 [Render](https://render.com/)。

Vercel 在前端部署、SSR 和 Serverless Functions 方面做得非常成熟；Render 则更适合运行常驻 Web 服务，也提供 PostgreSQL 等数据服务。

帽子云做的事情有点不一样：

**我希望把一个项目从网站部署到后端运行，再到数据库和缓存，都尽量放在同一个地方。**

可以从几个场景来看：

- **静态网站**：帽子云支持免费部署，共享每月 10 GiB 边缘流量；Vercel 更偏前端、SSR 和函数体验；Render 提供免费的 Static Sites。
- **Web 应用**：帽子云提供常驻容器，支持 Buildpack、Dockerfile 和镜像；Vercel 更偏 SSR 和 Functions；Render 提供 Web Service。
- **数据库**：帽子云提供 PostgreSQL 和 Redis；Vercel 通常通过第三方服务接入；Render 提供 PostgreSQL 和 Key Value。
- **网络**：帽子云支持项目内网连接；其他平台以对应服务和集成为准。
- **计费**：帽子云按人民币计费并支持微信充值；Vercel 按席位和用量计费；Render 分别计算计算、存储和流量等费用。

价格方面，参考两家官方公开价格：

- Vercel Pro：$20/席位/月，约 ¥135。
- Render Web Service：0.5 CPU / 512 MB 约 $7/月，约 ¥47。

官方价格：[Vercel](https://vercel.com/pricing) | [Render](https://render.com/pricing)。

如果你的项目主要是前端、SSR，Vercel 依然是很好的选择；如果需要运行常驻服务，Render 也有成熟的方案。

而帽子云更希望解决的是：**国内开发者能不能用一个平台，把一个完整项目从前端到后端都跑起来？**

这就是我们目前在做的事情。

## 三、哪些人适合使用？

我觉得下面这些场景都比较适合：

- **个人开发者**：部署博客、个人主页、开源项目文档。
- **独立开发者**：部署自己的 SaaS、Web 应用和 API。
- **小团队**：不想一开始就维护一套复杂的云服务器架构。
- **企业项目**：企业官网、管理后台、业务应用等。

举个例子。

你今天想部署一个个人项目，可以先创建一个静态网站。

过几天，项目需要登录、用户管理等功能，再增加一个 Web 应用。

后面需要保存数据，就创建 PostgreSQL；需要缓存，再增加 Redis。

整个过程不需要一开始就采购一整套云资源，按实际需要增加就可以了。

## 四、价格怎么样？

价格方面，我也尽量做得简单一些：

- **静态网站**：免费。
- **免费边缘流量**：每月 10 GiB，静态网站和 Web 应用共享。
- **超出流量**：¥0.43/GiB。
- **Web 应用**：约 ¥9.45/月起，起步规格为 0.5 核 / 512 MiB，持久卷存储另计。
- **PostgreSQL**：约 ¥10.53/月起，按规格和存储计费。
- **Redis**：约 ¥10.53/月起，按规格和存储计费。

静态网站和 Web 应用共用每月 10 GiB 免费边缘流量。

另外，新用户注册还会赠送 **¥20 体验金**。

具体规格和价格可以查看：[帽子云定价页面](https://maoziyun.com/pricing)。

## 五、接下来还会继续做什么？

从最初的静态网站部署，到现在增加 Web 应用、PostgreSQL 和 Redis，帽子云的方向也越来越清晰了。

我希望它不仅仅是一个部署网站的工具，而是一个开发者可以长期使用的项目托管平台。

以后做个人项目，不需要先研究一堆云产品，也不需要花很多时间处理基础设施。

代码提交上去，部署应用，需要什么服务就增加什么服务。

当然，目前还有不少地方需要完善，后续也会继续围绕应用运行、数据服务和基础设施做优化。帽子云可以减少部署、服务拼装和多平台切换的成本，但不会替代应用架构、数据库设计、备份恢复、安全配置和故障处理。
