# 一、Midalo 米搭是什么？
Midalo 米搭是一个多模型 API 接入平台。简单来说，它将不同的大模型接口集中到一个平台中，用户注册并创建 API Key 后，就可以按照文档调用平台提供的模型。
目前，Midalo 公开使用文档列出的模型覆盖：
- Claude
- GPT
- Gemini
- DeepSeek
- Grok
- GLM
- Kimi

除文本模型外，平台还提供图像生成、视频生成等多模态模型。具体可用型号、调用价格与线路分组，以站内模型广场的实时信息为准。
对于开发者而言，Midalo 的价值不只是“模型数量多”，更重要的是：可以用相对统一的方式管理模型接入、密钥、额度和使用记录。

# 二、为什么可以考虑注册 Midalo？

**1. 一个 API Key，减少多平台切换**

使用多个模型时，最麻烦的往往不是调用本身，而是需要分别维护不同平台的账号、密钥和余额。
通过 Midalo，可以在同一个平台中创建和管理 API Key，再根据项目需求选择不同模型。
例如：
- 编写代码时选择适合编程任务的模型；
- 处理长文本时选择上下文能力合适的模型；
- 日常问答或批量任务选择成本更低的模型；
- 需要图片或视频内容时，接入对应的多模态模型。

这样可以减少在多个平台之间反复切换的时间。

**2. 支持国内直连，降低接入门槛**

对于不方便配置额外网络环境的用户，Midalo 提供国内直连方式。

注册后，可以按照文档获取接口地址并创建 API Key，再将其填写到代码项目或支持自定义接口的客户端中。

对于刚接触大模型 API 的用户来说，这种方式可以减少前期环境配置工作，把精力集中在模型调用和功能开发上。

**3. 兼容 OpenAI、Anthropic、Gemini 原生协议**

不同模型平台采用的接口协议并不完全相同，这也是切换模型时经常需要修改代码的原因之一。
Midalo 公开文档显示，平台兼容：

- OpenAI 协议
- Anthropic 协议
- Gemini 原生协议

如果现有项目已经使用相关协议，可以根据文档调整接口地址、API Key 和模型参数，减少重复适配工作。
不过，不同项目的依赖库和调用方式可能不同，实际仍需以项目环境和 Midalo 接入文档为准。

**4. 按量计费，无强制月费**

对于个人开发者、独立创作者和小型团队来说，固定套餐未必总是划算。

如果项目处于测试阶段，或者每天调用量并不固定，按量计费通常更容易控制预算：

- 测试阶段可以少量充值；
- 调用量少时，不必承担固定月费；
- 可以根据任务选择不同模型和线路；
- 可以通过控制台日志核对实际用量与扣费。

Midalo 提供多线路分组，用户可以根据模型需求、预算和使用场景进行选择。具体费用以模型广场及控制台显示为准。

**5. 覆盖文本、图片和视频等使用需求**

Midalo 不仅面向文本对话和代码生成场景，也提供图像及视频生成相关模型。

这意味着，如果你正在开发一个包含多种 AI 能力的应用，可以尝试在同一平台中完成不同模型的接入，例如：

- 使用文本模型生成文章或产品描述；
- 使用图像模型生成配图；
- 使用视频模型制作短视频素材；
- 使用编程模型辅助编写和修改代码。

具体模型是否满足项目要求，建议先通过小额度测试确认效果、速度和成本。

**6. 提供常用工具接入教程**

即使不直接编写代码，也可以通过支持自定义 API 的客户端使用模型。

Midalo 公开文档提供以下工具的接入指引：

- Claude Code
- Cursor
- Cherry Studio

对于编程用户，可以将模型接入开发工具；对于日常办公和内容创作用户，则可以通过客户端配置模型接口。

相比完全手动部署，按照现成教程配置更容易上手。

# 四、如何注册并开始使用？

**第一步：打开注册入口**

 [你的专属邀请链接] 
也可以访问站点首页： https://agent.midalo.ai/

**第二步：创建账号**

按照页面提示填写注册信息，完成账号创建并登录控制台。

注册后建议妥善保管账号信息，不要将登录密码、API Key 或验证信息发送给无关人员。

**第三步：创建 API Key**

进入控制台后，找到密钥或令牌管理页面，创建新的 API Key。

建议根据不同项目分别创建密钥，例如：

- 编程工具使用一个 Key；
- 测试项目使用一个 Key；
- 正式应用使用一个 Key。

这样便于区分用途。如果某个密钥泄露，也可以单独停用，减少对其他项目的影响。

**第四步：选择模型和线路**

进入模型广场，查看当前可调用的模型、价格和线路分组。

选择模型时，不要只看模型名称，还应综合考虑：

- 是否适合当前任务；
- 输入和输出如何计费；
- 是否支持所需上下文长度；
- 是否支持图片、视频或工具调用；
- 当前线路是否满足项目预算。

正式接入前，可以先发送一条简单请求，确认配置是否正确。

**第五步：接入代码或客户端**

根据使用文档，将接口地址、API Key 和模型名称填写到项目或客户端中。

如果现有项目已经兼容 OpenAI、Anthropic 或 Gemini 协议，可以按照对应教程调整配置。

接入完成后，再逐步测试长文本、连续对话、代码生成等实际任务，确认效果符合预期。
