## 正文

原本我准备了 1,000 美金预算，让 Gemini 4 当公司高管，DeepSeek 打下手。让它们帮我写一个开源软件。

结果跑完这两天，**DeepSeek 只花了大约 10 美金（换算到我的 Token 套餐里，实际成本只要 1 美金），就把 [OpenCompare]( https://github.com/chaxiu/OpenCompare) 整套开源软件和自动维护闭环全部做完了。**

在这个过程中，我基本上只 prompt 过两次，指一个大方向，让 Agent 自行迭代，直到完成我的目标。

![Token 账单：5.9 亿 Token 仅花 12.64 美金](  )

### 1. 1 美金跑完 5.9 亿 Token ，DeepSeek 连产品经理的活都扛了

跑到现在，我们团队的分工自然演进成了这样：
**Gemini 作为公司最高负责人，平时基本只负责派发人类的指令，在产品负责人拿不准、不确定的时候才会被唤醒；而 DeepSeek 不仅扛下了全部研发，还承担了产品负责人（ Product Owner ）的职责。**

所以最终下来，Gemini 的 Token 消耗几乎可以忽略不计。
账单上，DeepSeek 独自跑了 **9,993 次请求、吞吐 5.9 亿 Token**（靠高缓存命中省下了大头），账面金额 **12.64 美金**，换算到我的 Token 套餐，**实际成本大约只要 1 美金。**

这 1 美金经历了多少迭代？看下面这张需求演进全貌图：

![OpenCompare 经历的需求集与 Agent 调度网络](  )

从双栏代码对比、三向合并、快照协议，到 Apple 开发者签名公证、三端打包发版，**4 大需求集、30 多个子需求、上百次 Agent 调度接力**，全是从我那两次大方向指令里自己长出来的。

### 2. Computer Use 亮眼表现：DeepSeek 的临场反应太聪明了

写完代码只是第一步，更让我惊喜的是 DeepSeek 在操控电脑（ Computer Use ）做真机验收时的表现。分享两个真实的测试 case：

**Case 1：Dock 栏呼不出来，它换思路打开 Finder 切「大图标」验 Icon**

OpenCompare 安装后，需要在电脑的 Dock 栏看到正确的 Icon 。
DeepSeek 自己控制电脑，把鼠标挪到了屏幕最底部，希望 Dock 能出现。结果受系统限制，并不支持。
DeepSeek 很聪明，立刻换了个思路：自己打开了 Finder 进入编译目录：

![打开 Finder 找到应用目录](  )

接着它把视图切换到了**「大图标」模式**，清清楚楚看清了 App 的 Icon ，顺利完成了任务：

![切换大图标模式看清 Icon 完成验收](  )

**Case 2：看不见系统弹窗，它直接定位窗口自己截图完成验收**

第二个 case 是「点击菜单能出现 About 弹窗」。
由于这个 About 弹窗是系统级窗口，默认不会出现在 OpenCompare 主窗口的视野里，一般的 AI 看不到变化就会反复重试。
DeepSeek 很聪明，直接从系统窗口列表里找到了这个独立的 `About OpenCompare` 窗口，自己截图看了一眼确认无误，一把完成了任务：

![找到独立系统窗口并截图完成验收](  )

### 3. 开源项目自动运营闭环

不仅软件做好了，它还建立了一套完整的开源项目维护闭环：

![OpenCompare 自动运营与应急哨兵](  )

现在每 15 分钟，「 GitHub 高频应急哨兵」就会自动监听 [chaxiu/OpenCompare]( https://github.com/chaxiu/OpenCompare) 的 Issue 和 Actions workflow ，发现问题自动修复、跑完桌面实机验收再发版。

当然，DeepSeek 这个版本的 OpenCompare 完成度怎么样，交给大家去评判：
👉 开源地址： https://github.com/chaxiu/OpenCompare

但它只花我预算的 **1/1000 （ 1 美金）** 就能交出这样的作品，我已经很满意了。
