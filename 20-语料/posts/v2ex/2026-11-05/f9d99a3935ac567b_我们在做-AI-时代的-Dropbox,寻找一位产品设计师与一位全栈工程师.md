## 正文

当年 Steve Jobs 想收购 Dropbox 时，说它“只是一个 feature ，不是一个 product”。但 Dropbox 坚持把文件跨设备同步做到了极致，最终定义了一种工作方式。

我们正在做 Hipo Hipo ，目标是做 AI 时代的同步中枢。

今天大家的工作流已经碎片化了：一会儿在 Cursor 写代码，一会儿切到 Claude Code 跑测试，明天换个新出的 Agent 摸索，后天换台设备继续。

但问题是：工具在变，记忆和上下文却无法流动。

传统云盘只认文件和元数据，看不懂段落间的逻辑，AI 无法穿透理解；

更多的关键信息——你的讨论过程、推翻过的方案、决策逻辑（我们称之为动态 State ）——根本没变成文件，最后全丢了。

Hipo Hipo 想做的，就是把你和各种 AI 协作时产生的内容与流动记忆（ State ），变成可随处携带、可随时挂载到任意 Agent 的工作空间。 无论你用什么工具、换什么电脑，你的上下文永远跟着你走。

让工作从绑定在特定“场所（ Place ）”，变成随身携带的“状态（ State ）”。

我们已完成清华系 VC 投资，Hipo Hipo 内测版现已上线，正在高速迭代与增长。急需以下两位伙伴：

1 、产品设计师 (Product Designer)

你要解决的问题：跳出传统 SaaS 软件界面的桎梏，重新定义“人和多 Agent 协同”时的交互界面。

我们希望你：

- 对 AI Native 的交互范式有极强的好奇心与审美直觉；

- 不只画漂亮的 UI ，更关注信息架构如何让“资料、上下文与进度”在不同工具间自然延续；

- 能快速出原型、动手能力强，愿意跟工程团队一起把天马行空的概念打磨成符合直觉的体验。

2 、全栈 / AI 工程师 (Full-Stack Engineer)

你要解决的问题：把“多端同步、上下文穿透、Agent 挂载”从设想变成极致丝滑的工程实现，并用技术驱动产品增长。

我们希望你：

- 精通 Web 前端与 macOS/iOS 生态交互，对桌面端/本地体验的细节有偏执；

- 具备扎实的后端架构与 Agent 协议/开发经验；

- 本身是重度 Coding Agent 用户（ Cursor / Claude Code / Codex 等），善于用现代 AI 工具百倍提升交付效率；

- 有增长黑客意识，敢写代码也敢跑增长实验。
