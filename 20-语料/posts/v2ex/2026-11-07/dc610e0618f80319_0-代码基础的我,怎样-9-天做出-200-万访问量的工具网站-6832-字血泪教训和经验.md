大家好，我是一个前市场营销从业者，前前媒体从业者，古早 Blog 作者。

对于 AI ，我本身的态度是拥抱的，但是对于真正意义上的 Coding 、创造，还是有很大心理障碍的。尽管我自封半个极客，和很多和我一样的朋友一样，自己也会鼓捣 NAS 、Docker 、VPS 、探针、流媒体、软路由、内网穿透……

但其实也仅限于一个普通科技发烧友的范畴。

大多数时候，我用 AI 都集中在 Chat 的场景：

> 问问生活中遇到的问题？想要讨论的文案？想要了解的规则和信息？

这一切的变化，来自于一个深夜的思考。我一直以来有一个痛点，从未被解决。

### 一切的开始，来自被 AWS 坑了 500 美金的我

由于我自己一些小的业务需求和单纯对于集邮 VPS 的爱好（这群人早期在 im286 、Admin5 、Chinaz ，后来到 Hostloc ，再到 NodeSeek ），买了很多 VPS ，其中也包含不同地域的亚马逊 AWS Lightsail 的实例。

本身 Lightsail 的套餐流量给的还算宽裕，单价最低的你可以用 7 美金买到 2T 的流量。但是这些流量需求本身是弹性伸缩的，也就是存在波峰、波谷。

流量超出有多贵呢？我们按最便宜流量区域价格，超出流量计费是 0.14 美金/GB ，也就是超出 1TB 流量费用会多出 92 美金。

去年我在 Lightsail 美东跑了一个做文件分发的小服务，有个月下载量突然起来了，月底看账单直接懵了：流量超额费 **$500**。

整个人原地飞升爆炸！！！

其实在整个 VPS 社群里面是有一些现成的解决方案的，比如通过探针远程或者脚本在本地，定期监测流量使用情况，提前发送预警。

但这些方案，更多满足的是为了不超出省钱，而没有满足弹性伸缩流量的需求。

事实上 AWS Lightsail 是有一套流量池的机制的，可以用来服务这种流量型服务的流量伸缩需求。它的规则包含但不限于：

- **同地区且同规格**的实例，流量可以叠加。（比如你买了两台 2T 流量的实例，一共能用 4T 流量；但，1T 、2T 、3T 这种不同规格的实例是不能叠加的。）

- 同规格的**双栈和纯 V6 实例**，流量可以叠加。

- 额度按存在时长折算，也就是 15 号你本身有一台新加坡的 2T ，流量快用完了，这时候你开一台 2T 到月底，实际你增加的可用流量是只有 2T 的一半，即 1T 。如果你中途销毁，增加的流量只算“总流量/(开机天数/30)”

- 流量和账单的计算时间，是按照标准的 UTC 时间，而不是按照各个区域时间，比如在中国是 UTC+8 。

以及还有一些 AWS 自身的一些坑，比如不提供实时的流量计算，只在账单中按天生成。以及不提供显示的流量池显示，这让我的钱包变得极其不可控。

在十月底的某个深夜，我想说要不然我来试试？没有人做那就我来做，反正自己也能用的到。

## 从 LSFee 走了很多“弯步”，走到 1ms.dog


![](  )


第一步我做的事情是找 AWS 、Lightsail 相关域名，通过 ChatGPT 找了一些都不是特别满意。特别长、特别不好记。

这时候想到，要不然找一个牛一点的、好记一点的。没准还能做一点其它的工具？


![](  )


这时候就开始转向了找一些通用的信息科技领域的名词，同时为了达成短、好记的目的。开始叠加考虑非主流小众后缀（传统主流是指 .com 、.net 等）

开始持续的跟 AI 来回切磋，我得到了一些启发。最后把焦点锁定在了“**1ms**”这个前缀上，它是大家在做 ICMP Ping 的时候，只有在局域网这种物理延迟极低的情况下才能够拿到的“最快”延迟，对于网络、科技有热爱的人，应该都能一眼 Get 妙妙含义。

于是就进入了枯燥的域名检索、排除注册、纳入备选反复循环中。最后我锁定了一个绝妙的域名：

> 1ms.one

前后都带 1 ，而且也够短，是不是很绝妙的选择？

于是在 AI 的比价帮助下，我顺利买下了这个域名。并且把它加到了我的 CloudFlare 里面去，看起来一切顺利可以开始开始真正干活了。

但我总感觉哪里有点不对，因为在我本地 VS  Code  编辑器里的可注册域名，还有一个似乎在发出隐约的光芒，这会不会是我看不到，但是它自己在努力照射我？

- 1ms.one

- 1ms.dog

看起来都是很完美的选择，选哪个都没错。并且 .one 后缀从物理意义上跟贴近我想要表达的含义。


![](  )


这时候我突然想起了如旋风般风靡世界，且至今仍然活跃在全球网络世界的狗头表情（**Kabosu**，于 2024 年离世）。

想说，要不然做点**不一样**的选择吧。


![](  )


就这样，15 个小时后，我推翻了自己的决定，把 **1ms.dog** 域名作为一切的起点。


![](  )


然后经过与 ChatGPT 的“轮番搏斗”，搏斗的过程堪称极致的惨烈、血腥，把 1ms 和 dog 这两个八竿子打不着的东西，艰难做出了 1ms.dog 现在的抽象 Logo 。

很多朋友后面对这个 Logo 的评价，都很中肯：丑陋、抽象、垃圾堆里捡来的 😢

## 不会 Vibe 的 Dog ，不是一个好厨师


![](  )


然后就进入了“并不艰难”的 Vibe Coding 阶段，我购买了 Claude Pro 20 美元订阅，很顺利地实现了第一个工具 [AWS Lightsail 省钱计算器]( https://ls.1ms.dog/)。

填上本月已用流量（或者只填一个预计的月总量），它会告诉你：

- **这个月安不安全**：安全 / 预计超额 / 已超额，会多付多少钱；
- **额度哪天用完**，还有几天可以补救；
- **加几台流量实例最省**：把加 0 、1 、2 、3 台的总花费摆在一起对比，最省的方案一键加进配置；
- **下个月怎么配**：按这个月的节奏给出建议。

并且在这个阶段，我逐渐摸清了自己想要的一些基础功能，这些功能和想法基本都延续到了后续的所有工具中，成为公共约束并持续得到扩展和管理。

- 原生支持 Dark/Light/Auto 模式切换，符合不同用户的需求，并且全站跨工具记忆。

- 原生支持 简体中文、繁体中文、英语、日语、韩语、西班牙语、法语、德语、葡萄牙语、俄语十种全球主流语言，根据用户语言自动切换。并且不同语言都是完全独立的静态页面，利于用户分享和搜索引擎查找。

- 对于可能需要二次分析或者自动化接入的，提供 Agent 的引入，并原生提供 /llms.txt 、/endpoints.json 等接口和工具。

- 所有功能和测试运行，尽可能在用户本地浏览器进行

  - 首先更符合用户真实的网络环境。

  - 其次服务端几乎不保留任何用户信息和记录，隐私侧更占优。

  - 静态化部署在“No Server”部署情况下更省钱，节省 SAAS 服务支出。

- 对于存在本地、VPS/Linux 远端两种不同测试需求，同时提供网页和脚本两种工具

- 提供完整的、清晰的 QA 供用户可视化查阅。

- 所有工具本身源代码，全量开源到 Github ，用户完全可审查或自行部署。

然后就进入了疯狂的 Vibe Coding 模式，这基本上是一个每天 12 小时不停顿的节奏。

需要指出的是，这里的很多工具，其实都已经有现成的产品了。

自己选择再做一遍有几个考量：

- 现有工具可能没有开放源代码

- 现有工具的实现方法无法满足我的需求

- 跟站内已有的工具有强关联，比如隐私探测和浏览器指纹、IP 纯净度、ASN 都有强关联。

在这里需要有一个对所有 AI 订阅服务有一个吐槽、一个建议：

> 第一是 5H 限制真的是史上最限制人类生产力的限制（即便我已经升级到 100 美元方案）
>
> 第二是订阅本身能否也按照周来付费，按需升降，匹配波峰波谷更合理。

Github 本身真的超级伟大，除了我在此前本身也受益于很多开源项目带来的便利之外。它最大的价值是提供了一个跨不同 AI Agent 的公共池，即使是某一天你更换 Agent ，或者电脑爆炸，也同样可以继续不受影响的开发。

## 从零开始 Vibe Coding 到自动化运营，我学到的一些有用的经验

1 、如果你是一个像我一样的多工具组合架构，请**一定要定义一个像我的“1ms-shell”一样的公共组件仓库。**

由它来管理协调工具会话，沉淀公共约定和共识。

这件事超级重要，能让架构在持续扩大中仍然保持低成本、高效率，让你的 Vibe 过程更愉悦。包括但不限于：

- 网站的公共组件：比如 logo 怎么放，分享流程如何进行，短链接如何生成，新组件导航条怎么更新。

- 网站的架构：都有什么工具？名字叫什么？仓库在哪儿？对应的 woker 是？域名是？

- 词汇表：跨语言的词汇统一，保持一致性，避免不同工具不同表述。

- 怎样部署：部署方式，可用资源，怎样避免冲突

这些内容都是以 Makrdown 文档的形式沉淀到私有仓库，是属于项目自己的智力资产，只要 Github 不倒闭，它就都在。

2 、如果你跟我一样，缺乏足够的服务器、代码基础、运营诊断知识。

那么在一个项目起步阶段，选择像 CloudFlare Worker **这样的“No Server”部署会极大节省你的时间和效率**，事实上这样类似的服务在国内和全球范围内都有很多的选择。

他们跟 AI Agent 结合在一起，基本能实现完全自动化的部署、上线、测试、分析，能省大力气。


![](  )


3 、**能自动化的就自动化，绝不动手。**

包括但不限于：

- 1ms.dog 的检测错误/故障报修，完全自动化运行。自动提交到 Github issues ，每一个小时自动定时审查判断，符合条件的自动分配给对应工具会话，解决完成后关闭 issue ，还会自动邮件通知用户。

- 每天定时审查流量情况、异常报错、用户反馈、仓库提交，每天自动生成整个工具站的分析报告、提升建议、新功能建议。

- 每天分析当天的会话情况，把有价值的规则、约束、共识，沉淀到私有公共组件仓库。

4 、在每次对话清楚，你还是要尽可能明确需求，避免反复修改浪费时间、浪费钱包。

5 、对于不懂、不明确的地方，可以勇敢发问

6 、可以多尝试多个 AI 进行组合，比如有的 AI 调研、有的 AI 规划、有的 AI 做图，有的 AI Coding 。或者同一个不明确的问题，同时向多个 AI 发问，有时候会有意外惊喜。

## 从 0 到 200 万，完全是一个意外的无心插柳

本来这个故事，按这样常规的剧情走下去，就是一个纯爱版的用爱发电的 IT 工具站，慢慢加着自己需要的功能，向科技社区、开源社群贡献微不足道的一点力量。

但是就像世间大部分的事情一样，意外总是在你想不到的时候到来。


![](  )


某天早上一起床，有用户半夜给我发消息说你网站炸了。

我心说不可能啊，CF 这么大公司，还能因为我这一个小小的网站爆炸？🐶

11 月 1 号，本月的“**第一天**”，10 万次请求就消耗光了。要知道我这是一个几乎纯静态的工具站，而 CF Worker 的静态资源请求是完全免费的。

每个网页打开，只有公共的导航条会消耗 1 次请求。

**认真的吗？是我吗？我这个刚搓出来的工具站？ 10 万个访问烧光？ CF 你是不是背着我偷我钱了？**

算鸟算鸟，掏钱掏钱。


![](  )


本月截止到今天（ 5 号），差不多是 192 万的访问量，单小时峰值最高 5 万。

![](  )

Worker 请求用量，跑到了 460 万，感觉这个月肯定要额外再给 CF 掏钱了。跑不掉了。

来到大家最关心的话题，是什么给你带来了这么大的流量？

说实话很意外，我们做了一个工具叫“[你是谁]( https://who.1ms.dog/)”，它的本质是一个浏览器指纹探测器，在不调用额外权限的情况下，告诉用户纯 WEB 的方式，网站可以获取到你的哪些信息。

为了更好的把这些信息可视化，我们用拟人化的手段把这些结果描述了出来。同时也花了时间认真设计了分享卡片和分享组件。


![](  )


然后有用户发现这个检测的结果很有意思，分享到了外部社区，然后就引爆了链式分享和讨论。包括但不限于：

- 隐私惊叹，网站居然能拿到这么个人信息。

- 搞笑的身份错位，我怎么变成了新加坡人

- 结合画像去讨论 AI 封号焦虑

真就是没什么技巧、规划、计谋，典型的无心插柳带来的意外结果。

写这篇文章的本意，也是希望分享自己这 9 天的历程，希望对出于同样情况、有需要的朋友们有帮助。

对于工具站本身也没有太大的影响，我也会持续的去迭代和创造更多我自己和大家需要的工具。

PS ，网站顶部的报告问题超好用，如果有问题欢迎通过它来提交到自动化流程。
