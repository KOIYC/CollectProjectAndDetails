# 命名与目录规范

> **一句话**：文件名不是「看起来整齐」就行 —— 它是 **wikilink 的解析键**、**采集端的写盘路径**、
> **去重账本的指针**。名字错一层，断链、双份语料、计数错位就全来了。
> 本页是唯一规范；执行靠 `tools/kb_name_audit.py`（审计）+ `tools/kb_navfix.py --fix-names`（改名）。

## 一、命名规则总表

| 对象 | 模式 | 例子 | 谁生成 / 谁改 |
|---|---|---|---|
| 语料页 | `20-语料/posts/<渠道id>/<发布日>/{item_id}_{slug(title,50)}.md` | `20-语料/posts/hn_show/2026-09-18/e63b2ecea541875f_Show-HN-Omabib...md` | `kb_collect` 生成；**改名只允许 `kb_navfix --fix-names`** |
| 项目页 | `10-项目/{slug(name,48)}_{url指纹8}.md` | `page-rage.com_ead86953.md` | 同上 |
| 人物页 | `30-人物/{slug(name,40)}_{url指纹8}.md` | `Pieter-Levels_1f6c289c.md` | 同上 |
| 方法论页 | `40-方法论/{slug(title,40)}_{url指纹8}.md`（hash 加 `#method` 盐）| `Tony-Dinh-$45K-mo-Indie-Hacker-Jo_a1b2c3d4.md` | 同上；盐的存在见 `kb_collect.method_note_path` 注释 |
| 渠道页 | `50-渠道/{渠道id}.md` | `hn_show.md` | `kb_collect`；渠道id 在 `_meta/channels.yaml` 注册 |
| 原始归档 | `90-原始/<渠道id>/<日期>.jsonl` | `90-原始/hn_show/2026-09-20.jsonl` | `kb_collect`，**只追加、不改名** |
| 时点型报告 | `00-索引/报告/<类型>-<YYYYMMDD>.md` | `洞察-20260920.md`、`修复报告-20260920.md`、`分析-20260920T025555.md` | 工具生成，**追加不覆盖** |
| 快照型报告 | `00-索引/报告/<类型>.md`（无日期） | `命名审计.md`、`存量重判报告.md`、`回填队列.md`、`内容审计-all.md` | 工具生成，**每次覆盖**，只保留最新 |
| 索引页 | 固定名 | `Home.md`、`AGENTS.md`（根）；`浏览`、`项目地图`、`归档与申诉`、`报告总览`、`字段字典`、`渠道台账`、`运行日志`、`待办与决策`（00-索引） | 脚本/人工，名字**不可改**（被全库引用） |
| 目录说明页 | `<目录主题>说明.md` | `30-人物/人物页说明.md`、`40-方法论/方法论页说明.md` | 人工 |

**关键区别——时点型 vs 快照型**：时点型带日期（历史可回看，链接永不失效）；
快照型无日期（永远被覆盖，**引用它等于引用一个会变的页面**，只适合当「当前状态」入口）。

## 二、文件名字符规则（`kb_common._BAD`）

文件名禁止：

| 字符 | 原因 |
|---|---|
| `< > : " / \| ? *` 与控制符 | Windows 文件名非法 |
| `[ ] # ^` | **Obsidian wikilink 语法字符**：`#`=标题锚点、`]`=链接收尾 → 谁引用谁断链（实测 13 文件 → 20 死链） |
| `` ` `` | 让断链检查器把指向它的链接当「正文伪代码」跳过 → 检查盲区（实测 1 文件） |

其他纪律：

- **全库 stem 必须唯一**（跨目录也算）：`[[短名]]` 按文件名解析，撞名结果不确定。
  这就是目录说明页不叫 `README.md` 的原因（两个目录各一份说明 = 必撞）。
- **同目录大小写视为同名**（Windows 文件系统不区分大小写，`Foo.md` 与 `foo.md` 互相覆盖）。
- **改名只有一条路**：`kb_navfix.py --fix-names` —— 它按**记录反算**规范名
  （不是把现名 sanitize 一遍，否则连字符/截断边界会差一两个字符，改名当天不漂、下一轮就漂），
  并同步 `seen.json` + 改写全库链接 + 写 undo manifest。

## 三、目录框架（Johnny.Decimal 式，两位前缀 = 稳定地址）

| 前缀 | 目录 | 职责 | 事实源地位 |
|---|---|---|---|
| 00 | `00-索引/` | **导航层**（入口/地图/台账/规范）+ `报告/` 生成物 | 不是事实，是指路牌 |
| 10 | `10-项目/` | 项目实体页（gold） | 由语料派生，可重建 |
| 20 | `20-语料/` | 语料主力（silver），`posts/<渠道>/<发布日>/` 两层分桶 | 清洗后语料 |
| 30 | `30-人物/` | 人物实体页 | 同 10 |
| 40 | `40-方法论/` | 方法论沉淀（人工/LLM） | 唯一人工创作区 |
| 50 | `50-渠道/` | 渠道健康台账页 | 状态快照 |
| 60 / 70 | **（保留）** | 60=分析产物、70=合作/候选池等未来需求；启用前先改本页 | — |
| 80 | `80-归档/` | `posts/`（判废语料）+ `项目/`（移出检索面的实体页） | **移出检索面 ≠ 删除**，undo 清单在 `_meta/` |
| 90 | `90-原始/` | 原始 JSONL（bronze） | **唯一事实源，只追加、不可变** |
| — | `_meta/` | 账本与状态（seen/channels/schema/manifest） | 脚本读写，**不许手改** |
| — | `tools/` | kb_* 工具链 | 人工维护 |
| — | 根目录 | 只放 `Home.md`（人）+ `AGENTS.md`（AI） | 两个入口，不放别的 |

**框架纪律（违规会被审计抓住）**：

1. **顶层只允许上表目录** —— 新需求先进保留位（60/70）或写进本页，不开新顶层。
2. **MOC / 地图只放 `00-索引/`** —— 数据目录被计数脚本按 `*.md` glob
   （healthcheck 等式①②），塞 index 页会把「647 个项目」变 648。
3. **归档区是冻结区**：`80-归档/` 不做规范名核对、不追新字段；改名也仅限语法字符清理。
4. **索引目录不放报告**：`00-索引/` 根只放导航；生成物进 `00-索引/报告/`。

## 四、执行闭环（谁检查、谁修）

```bash
python tools/kb_name_audit.py              # 审计：语法字符 / stem 歧义 / 规范名漂移 / 框架越界
python tools/kb_navfix.py --fix-names --dry   # 看会改哪些（判据 = 记录反算）
python tools/kb_navfix.py --fix-names         # 真改名（manifest + seen 同步 + 链接改写）
python tools/kb_navfix.py --fix-names --dry   # 复跑必须为空（幂等验证）
python tools/kb_healthcheck.py             # 五项不变量收尾
```

审计判据 = 修复判据（同一个 `slugify` / 同一套记录反算），所以「审计清零」等价于
「下一轮采集不会再写出第二份语料」。**任何手改文件名都算违规** —— 手改不写 manifest、
不同步 seen.json、不改链接，三件全漏。
