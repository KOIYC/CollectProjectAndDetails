# 字段字典

> 机器可读版本：`_meta/schema.json`（**权威**；改字段先改它，再同步本文）。

## 四类 note 的 frontmatter

### 1. 语料 note（`20-语料/posts/...`）

| 字段 | 说明 |
|---|---|
| `type` | 固定 `corpus` |
| `item_id` | `sha1(规范URL)[:16]`，跨运行去重主键 |
| `source` / `source_name` | 渠道 id / 显示名 |
| `url` | **原帖 URL（必填，出处）** |
| `project_url` | 项目自身站点/仓库（与 url 区分） |
| `author` / `published_at` / `lang` | 作者、发布时间、语种 |
| `captured_at` | 采集时间（+08:00） |
| `kind` | `post` / `project` / `person` / `method` |
| `topic` | **赛道标签**（见下「topic 枚举」）。采集时写入，历史条目由 `kb_navfix.py` 补齐 |
| `shard` | **采集批次日**（= 落盘目录名，如 `2026-09-20`）。纯字符串 |
| `pub_day` | **发布日**（`published_at` 前 10 位，如 `2026-09-17`）。纯字符串 |
| `metrics` | 平台指标（points/comments/stars/score/play/replies…） |
| `comments_count` / `comments_total` / `comments_truncated` | 评论抓取量 / 平台总量 / 是否截断 |
| `discovered_via` | 发现路径（如 `reddit:7d`、`exa:<query>`） |
| `tags` | 固定含 `语料` + 渠道 id + 平台分类 |

> **`shard` / `pub_day` 为什么是独立字段**：Bases 的 `groupBy` 直接对 ISO 时间串分组会
> 「一条一组」（等于没分组），所以时间轴需要纯字符串日字段。两者含义不同 --
> `shard` 是**我们入库的批次**，`pub_day` 是**内容发布时间**，做趋势分析必须用 `pub_day`。

正文结构：`## 正文` → `## 评论（N/总数）` → `## 关联链接` → `## 导航`。

**`## 导航` 段是结构刚需**：语料页必须出链到项目页/人物页/渠道页 + [[浏览]]。
缺了它整库就是死胡同（实测 723 条语料页曾一条 wikilink 都没有，只能靠文件树翻）。
由 `kb_collect.py` 写入；历史条目由 `kb_navfix.py` 补齐。

### 2. 实体 note（`10-项目/` 与 `30-人物/`）

| 字段 | 说明 |
|---|---|
| `type` | `project`（人物页为 `person`） |
| `title` / `project_url`（人物为 `profile_url` / `handle`） | 项目链接 / 主页 |
| `first_seen` | 首次收录时间 |
| `sources` | 出现过的渠道 |
| `stale` | `true` = **已无在库语料指向它**（对应语料被归档）。只打标不搬家，条目回到在库会自动摘除 |
| `tags` | `项目`/`人物` + 渠道 + 分类 |

正文含 **## 观测历史** 表（采集时间 / 渠道 / 指标 / 语料 wikilink），用于看「是否在变热」。

> `stale` 由 `kb_prune.py --liveness` 维护。必要性：归档只搬语料 note、**不动**实体页，
> 于是实体页数会一直领先在库条目数（实测 818 vs 710）——「项目池」视图会混进一堆
> 已经没有在库语料的项目。

### 3. 渠道 note（`50-渠道/`）

| 字段 | 说明 |
|---|---|
| `type` | 固定 `channel` |
| `channel_id` / `name` / `group` / `adapter` | 注册表字段快照 |
| `auth` | `none` / `cli` / `browser` |
| `status` / `last_verified` | 最近一次运行状态与日期 |
| `params` | 取数参数（queries/subs/tags/限流） |

正文含 **## 运行历史** 表（时间/状态/条数/耗时/消息）。

### 4. 索引 / 报告 note

| `type` | 位置 | 例 |
|---|---|---|
| `home` | 根目录 | `Home.md`、`AGENTS.md`（给 AI 的说明） |
| `index` | `00-索引/`（导航层） | [[浏览|从这里开始]]、[[项目地图]]、[[归档与申诉]]、[[字段字典]]、[[渠道台账]]、[[运行日志]]、[[待办与决策]] |
| `report` | `00-索引/报告/`（生成物） | `洞察-*`、`修复报告-*`、`内容审计-*`、`分析-*`、`存量重判报告`、[[报告总览]] |
| `index` | `30-人物/` | 人名录页（`type: index` + `tags: [人物]`） |

> 导航与报告**必须分目录**：索引目录一旦被带时间戳的报告淹没，它就不再是索引。
> 报告类工具栏在 [[浏览|从这里开始]] 第 0 节给入口；报告本身先看 [[报告总览]]，不用进目录翻。
>
> **地图（MOC）只放 `00-索引/`，不放数据目录里**：`10-项目/`、`20-语料/` 等被计数脚本
> 按 `*.md` glob（healthcheck 等式①②），塞 index 页会当场污染计数（647 变 648）。
> `aliases` 是合法解析目标：healthcheck ④ 按「路径 + 文件名 + frontmatter aliases」三路解析。

## 归档标记（`80-归档/` 下的语料页）

| 字段 | 说明 |
|---|---|
| `archived` | `true` = 已被存量重判判为无关 |
| `archived_at` | 归档时间 |
| `archive_reason` | 判定原因（可追溯是哪条规则杀的） |

归档可逆：`kb_prune.py --undo _meta/prune_manifest_<ts>.json` 按清单搬回。
**审计口径必须用「在库」而非 raw** —— `90-原始/` 只追加，归档不改它；
直接读 raw 会让「归档」这个动作在报表上永远看不出来（可用率会一直卡在旧值）。

## 状态枚举

| 值 | 含义 | 处理 |
|---|---|---|
| `ok` | 成功且有数据 | 继续 |
| `empty` | 连通但窗口内无符合数据 | 观察；连续 3 次 → 调阈值或停用 |
| `error` | 取数/解析失败 | 人工 review |
| `auth` | 缺登录态（小红书/X） | 提示解锁，**不算已覆盖** |
| `disabled` | 已登记停用 | 看复活条件 |

## kind 枚举

| 值 | 用途 |
|---|---|
| `post` | 发布帖 / 讨论帖 —— **语料主力**（正文 + 评论） |
| `project` | 产品条目（发布站、名录、榜单） |
| `person` | 作者 / 独立开发者画像 |
| `method` | 复盘、方法论、收入报告 |

## topic 枚举（赛道）

由 `kb_common.TOPICS` 词表按「标题 + 正文前 4000 字」**首个命中**判定；都不命中 → `未分类`。

`AI 工具/Agent` · `开发者工具` · `SaaS/B2B` · `电商/独立站` · `内容/媒体` ·
`教育/学习` · `健康/生活` · `游戏` · `移动 App` · `浏览器扩展` · `未分类`

> 口径提醒：赛道分布反映的是**渠道结构**（HN Show / GitHub / 发布站天然偏开发者与 AI），
> 不是市场结构。别拿它当「哪个赛道机会大」的证据。

## 三条硬规矩

1. **`url` 必填**：所有语料必须可回溯出处；抓不到 url 的条目直接丢弃。
2. **截断必须标注**：评论/正文被截断时写 `comments_truncated: true`，分析时须意识到样本偏差，不允许静默截断。
3. **每页都要有出口**：语料页必须有 `## 导航` 段 —— 任何 note 都不该是终点。
