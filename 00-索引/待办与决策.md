## 决策记录

| 日期 | 决策 | 理由 |
|---|---|---|
| 2026-09-20 | **kind 语义优先于 project_url 等证据**：`is_project_ish` 对 person/method 直返 None | 让证据覆盖语义会把「独立开发者的收入复盘」错分到 `10-项目/`（实测 exa_discovery 9 条、c1c7 6 条即如此）；语义明确时不看证据 |
| 2026-09-20 | **method 页 hash 用 `#method` 盐**（person 页暂不加，踩过再补） | 同一 URL 既被归档为项目页又被建为方法论页时，slug(url, 8) 撞名（实测 Tony-Dinh 一例）；盐按 kind 隔离 hash 空间 |
| 2026-09-20 | **healthcheck ⑥ 是软门，不改「五项全绿」口径** | 孤立语料 = 数据可访问性问题（Obsidian 图谱里不可达），不是数据完整性问题；①-⑤ 任一非零 = 改动错了，⑥ 非零 = 有历史自愈债 |
| 2026-09-20 | **`kb_navfix --fix-links` 扩到能吃 `[[含[]的旧路径]]`**：junk-stripped basename 唯一命中即改写 | 反引号/中括号类改名会留下路径式链接指向不存在的旧 stem；此前 `LINK_JUNK` 一律跳过，等于把「改名没跟链」的债务永久挂账 |
| 2026-09-20 | `_BAD` 加入**反引号**；全库 stem 必须唯一（说明页不叫 README） | 反引号让断链检查器跳过指向它的链接（检查盲区）；`30-人物` 与 `40-方法论` 各一份 README → `[[短名]]` 解析歧义。规范固化在 [[命名与目录规范]] |
| 2026-09-20 | 目录说明页命名 `<主题>说明.md`；`80-归档/` 定为**冻结区**（不做规范名核对） | stem 唯一性要求；归档=冻结快照，规则变了他也不该跟着改名 |
| 2026-09-20 | 报告分**时点型**（带日期，追加）与**快照型**（无日期，覆盖） | 两类的引用语义完全不同：时点型链接永不失效；快照型只当「当前状态」入口 |
| 2026-09-20 | 入口页**不改文件名**，改 H1/title + aliases | `[[浏览]]` 被 729 个文件引用；改名 = 全库 churn，收益不抵（调研报告自身的标尺：不减少「找不到」次数的改动就是净成本） |
| 2026-09-20 | MOC 落在 `00-索引/`，**不**落在 `10-项目/` 等数据目录 | 计数脚本按 `*.md` glob 数据目录；塞 index 页会污染「647 个项目」这类数字 |
| 2026-09-20 | healthcheck ④ 补 alias 解析 | 检查器必须和 Obsidian 一样宽（路径 + 文件名 + alias），否则它逼人写更差的链接文本 |
| 2026-09-20 | 「过滤是查询不是导航」写进入口页 | Bases 视图要求先知道找什么；导航（分组地图）必须与查询（过滤）并存 |
| 2026-09-20 | 采集用**脚本**、编排与渠道判断用 **skill**、定时用 **automation** | 纯脚本无法发现渠道腐化；纯 skill 逐条 shell 太慢太贵 |
| 2026-09-20 | 语料深度＝**全量正文 + 全部评论 + 关联链接** | 用户选择：供后续 AI 深度分析，元数据不足 |
| 2026-09-20 | 零第三方依赖（纯 stdlib） | 本机 PyPI 不可达；顺带获得可移植性 |
| 2026-09-20 | 通用正文后端从 Jina 换 **Exa web_fetch** | 实测 Jina `r.jina.ai` 502/HTTP 000 不可用（doctor 却声明 ok → 记 delta） |
| 2026-09-20 | Reddit 用 `settle_days=3` 沉淀窗口 | 镜像 score 装载延迟：近 3 天帖 max=1，7-14 天前 max=42 |
| 2026-09-20 | V2EX 走 **sov2ex** 而非官方 API | 官方 API 本网络 502；sov2ex 免登录且含正文 |
| 2026-09-20 | 停用 Fazier / HuggingFace / DecoHack / IH-Algolia | 404 / 网络不可达 / 无增量 / key 403（均留复活条件） |
| 2026-09-20 | 语料按 `20-语料/posts/<渠道>/<日期>/` 分桶 | 避免复现 find project「根目录 168 个文件」的堆叠问题 |
| 2026-09-20 ✅已修 | `kb_name_audit` 报告改为**不带 wikilink** 的纯文本路径 | 报告用 `[[页名]]` 引用违规页 → 报告自身成为引用方，永久拦住 `--archive-entities` 搬走被点名的 stale 页（自引用怪圈，实测 28 页被自己拦） |
| 2026-09-20 | 实体页订正后的标准收尾序列固化：`liveness --apply → kb_moc → archive-entities --apply → kb_insight --browse` | 订正改 project_url/ kind 会产生孤儿页；跳过 liveness 或先搬后更地图都会被引用拦下（本轮实测） |
| 2026-09-20 | **全库入 git**（GitHub `KOIYC/CollectProjectAndDetails`，main）并作为收工步骤 | 此前「无 git，删除不可恢复」——kb_qc.py 不敢删、manifest 不敢轮转；入库后 undo 凭证有第二份保险，工具改动可 revert。红线不变：生成页/文件名仍不许手改 |
| 2026-09-20 | **判定常量留在 kb_common，不外置 rules.yaml** | rules.yaml 只放主题准入词表这类运营可调项；判定常量（BODY_MIN/SUMMARY_TAIL/KIND_EXEMPT）与消费它的代码必须同版本演进，外置反增「改了 yaml 忘了改代码」的漂移面 |
| 2026-09-21 | **语料分片日期 = 首次落盘日，raw 分片日期 = 记录进账日，两者各取各的**（`kb_common.note_bucket` 以 seen 现存 note 为准，不许用最新 raw 的日期） | 跨零点重跑会把「回填日」当新分片 → note 被重建、旧文件成孤儿。2026-09-21 零点连跑两轮 backfill 实测 45 个孤儿、① 当场破功 |
| 2026-09-21 | **healthcheck ⑤ 扩为「磁盘 ↔ 账本」双向差集**（slug 漂移 + 孤儿页 + 幽灵账） | 原实现拿文件自己的日期桶重算，恒等于自身 → 漂移永远 0，上面那 45 条一路报绿。检查器必须同时能看见「在盘不在账」和「在账不在盘」 |
| 2026-09-21 | **`kb_prune` 搬完必须自验**（`from` 已不存在 ∧ `to` 已存在），未生效的进 `manifest.unverified` 并响亮告警 | 实测 6 moves 挂 3 条：源文件还在 → 下一轮重判把同一条再归档一次，归档区同条两份。「看起来成功」和「搬成了」不是一回事 |
| 2026-09-21 | **冻结区同条目多份 → `--dedupe-archive` 只移不删**（保留 `seen.note` 指向的那份，其余进 `80-归档/重复副本/<ts>/`） | 撞名顺延 `-dupN` + 跨天重复归档会造出一条 4 份（实测 5 组 15 份）。保留规则必须优先账本指向的那份 —— 留最新的那份会让磁盘与账本脱节；冻结区不做不可逆删除 |
| 2026-09-21 | **收工必须 commit**，不只要 healthcheck 绿 | 实测 212 处未提交堆到第二天：git 是 undo 的第二份保险（manifest/undo 清单丢了还能捞），不入库等于裸奔 |
