- [x] **B2 元数据契约门禁**：**没有新建 `kb_metadata_gate.py`，而是并进 `kb_analyze.py`** ——
      门禁与取数诊断读的是同一份 profile、同一批条目，拆成两个工具只会让「该字段该不该有」两处定义、

      **实测**：真缺陷 67（betalist 发布日 56 · c1c7 project_url 5 · exa_discovery 发布日 5 · 小红书 1）；
      声明豁免 50（IH 发布日 43 · c1c7 发布日 7）（2026-09-21）
- [x] **B3 抽取器基准**：新工具 `tools/kb_fetcher_bench.py`，出 [[抽取器基准-20260921T221933]]。
      同批 12 条 URL × direct/exa/gh，按命中率·中位字符·贴上限率·结尾完整率选后端。
      **实测**：direct 命中 66.7% / 中位 2952 字符 · exa 58.3% / 2709（且慢 5 倍：76.6s vs 15.2s）·
      gh 8.3% / 72290（只对 GitHub URL 有效）。**结论 = 直取仍应为首选**，但两类硬缺口要记在台账上：
      `news.ycombinator.com`（Tunnel 502）、`youtube.com`/`twitter.com`（502/握手超时），
      这些只能交给 Exa 兜底 —— **切后端要有这张表，不靠「谁先报 ok」**（2026-09-21）
- [x] **B4 死信账本结构化升级**：并入 `kb_backfill.py`（schema 2）。
      每条死信带 `reason_code` / `tried[]` / `http_status` / `reason_first`（保留原始 reason 作审计留痕），
      新增 `--dead-report`（按 reason_code 分组）、`--revive-code`（按代码复活）、`--migrate-dead`。
      **踩到的坑**：第一次迁移后出现「同样的 reason_code 却 reason 文本不同」——复活过的条目 reason 被改过、
      结构化字段没跟着改 → **一致性破损**。修法：`reason` 一律由 `reason_code` + `tried[]` 重建，
      但**结构性原因（媒体帖/账号页）保留领域知识文案不重建**（重建会丢信息）。
      **实测**：220 → 63 条，分布 no_backend 20 · media 19 · unreachable 10 · gh_miss 10 · account 3 · http_403 1（2026-09-21）
- [x] **B5 近重复检测（在线 + 离线）**：新工具 `tools/kb_near_dup.py`，出 [[近重复-20260921T222325]]；
      采集端**在线**标注（`kb_collect` 写 `extra.near_dup_of`）。
      **第一版是错的，留档**：只用「字符 4-gram simhash + Δ≤6」→ 把 **8 个毫不相关的 GitHub 项目判成一组**
      （实测互相 Δ0~1，而真实 4-gram 包含度只有 0.15~0.27）。两个机制叠加：模板行（`- Stars: N`）反复投票
      淹掉真信号 + 字符 4-gram 的公共基线太强。
      **改法 = 两段式（候选 ≠ 重复）**：特征换**词级 3-shingle 且先去重**（断机制 1），
      simhash 只当**候选生成器**，命中候选必须过**精确特征包含度 ≥0.60** 才算重复。
      阈值可证伪：报告打印全库基线 —— 中位 0.000 / P99 0.019 / 最大 1.000（116 万对），0.60 落在真空带里。
      **实测**：1527/1732 条有指纹 · 近重复 12 组（跨渠道 2）· 候选被否 0 对；
      两条跨渠道组都是 hn_front × lobsters 同标题同文（包含度 1.000），旧版误判组已归零。
      `--selftest` 5/5（真改写命中 0.81~1.00 · 同域异文 0.00）（2026-09-21）

## 决策记录

| 日期 | 决策 | 理由 |
|---|---|---|
| 2026-09-20 | **kind 语义优先于 project_url 等证据**：`is_project_ish` 对 person/method 直返 None | 让证据覆盖语义会把「独立开发者的收入复盘」错分到 `10-项目/`（实测 exa_discovery 9 条、c1c7 6 条即如此）；语义明确时不看证据 |
| 2026-09-20 | **method 页 hash 用 `#method` 盐**（person 页暂不加，踩过再补） | 同一 URL 既被归档为项目页又被建为方法论页时，slug(url, 8) 撞名（实测 Tony-Dinh 一例）；盐按 kind 隔离 hash 空间 |
| 2026-09-20 | **healthcheck ⑥ 是软门，不改「五项全绿」口径** | 孤立语料 = 数据可访问性问题（Obsidian 图谱里不可达），不是数据完整性问题；①-⑤ 任一非零 = 改动错了，⑥ 非零 = 有历史自愈债 |
| 2026-09-20 | **`kb_navfix --fix-links` 扩到能吃 `[[含[]的旧路径]]`**：junk-stripped basename 唯一命中即改写 | 反引号/中括号类改名会留下路径式链接指向不存在的旧 stem；此前 `LINK_JUNK` 一律跳过，等于把「改名没跟链」的债务永久挂账 |
| 2026-09-20 | `_BAD` 加入**反引号**；全库 stem 必须唯一（说明页不叫 README） | 反引号让断链检查器跳过指向它的链接（检查盲区）；`30-人物` 与 `40-方法论` 各一份 README → `[[短名]]` 解析歧义。规范固化在 [[命名与目录规范]] |
| 2026-09-20 | 目录说明页命名 `<主题>说明.md`；`80-归档/` 定为**冻结区**（不做规范名核对） | stem 唯一性要求；归档=冻结快照，规则变了他也不该跟着改名 |
| 2026-09-20 | 报告分**时点型**（带日期，追加）与**快照型**（无日期，覆盖） | 两类的引用语义完全不同：时点型链接永不失效；快照型只当「当前状态」入口 |
| 2026-09-20 | 入口页**不改文件名**，改 H1/title + aliases | `[[浏览]]` 被 729 个文件引用；改名 = 全库 churn，收益不抵（调研报告自身的标尺：不减少「找不到」次数的改动就是净成本） |
| 2026-09-20 | MOC 落在 `00-索引/`，**不**落在 `10-项目/` 等数据目录 | 计数脚本按 `*.md` glob 数据目录；塞 index 页会污染「647 个项目」这类数字 |
| 2026-09-20 | healthcheck ④ 补 alias 解析 | 检查器必须和 Obsidian 一样宽（路径 + 文件名 + alias），否则它逼人写更差的链接文本 |
| 2026-09-20 | 「过滤是查询不是导航」写进入口页 | Bases 视图要求先知道找什么；导航（分组地图）必须与查询（过滤）并存 |
| 2026-09-20 | 采集用**脚本**、编排与渠道判断用 **skill**、定时用 **automation** | 纯脚本无法发现渠道腐化；纯 skill 逐条 shell 太慢太贵 |
| 2026-09-20 | 语料深度＝**全量正文 + 全部评论 + 关联链接** | 用户选择：供后续 AI 深度分析，元数据不足 |
| 2026-09-20 | 零第三方依赖（纯 stdlib） | 本机 PyPI 不可达；顺带获得可移植性 |
| 2026-09-20 | 通用正文后端从 Jina 换 **Exa web_fetch** | 实测 Jina `r.jina.ai` 502/HTTP 000 不可用（doctor 却声明 ok → 记 delta） |
